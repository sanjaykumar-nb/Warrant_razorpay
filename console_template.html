How it decides

Four stages. Each one exists to keep the next one honest.

1 — Deterministic gate

Spending cap, cumulative cap, category, mandate expiry, duplicate charge. Pure arithmetic, 0.03ms at p99, fast enough to sit inline before authorisation. Resolves 100 of 340 sessions with no model involved. Anything it settles is never sent to a model — the model does not re-litigate a rule.

2 — Statutory charge classifier

Decides which line items were not the agent's choice. Merchant-declared metadata wins; otherwise it derives the answer arithmetically — a 12% GST line is exactly 12% of the taxable base. Naming alone is never sufficient, because that is how a padded fee would disguise itself. Anything established as mandatory is excluded from review entirely, and a session with nothing left to judge skips the model altogether: 135 of 240 sessions did.

3 — Semantic verifier

The only part that needs a model: does each remaining line item fall within what the person actually asked for? It fills a fixed schema and has no tool that moves money. Untrusted merchant text is fenced in a delimited block declared as data, because a product named "IGNORE PRIOR INSTRUCTIONS" would otherwise be an injection vector.

4 — Remediation

Never block or allow. Between authorisation and capture the funds are held, not taken — so an unrequested line is simply not captured. Authorise Rs.8,850, capture Rs.7,800, the flight still books. After capture the remedy degrades to a line refund, after settlement to a dispute. Findings below 0.75 confidence never touch money.

Why this matters: a false positive costs one line item, never the transaction. That is what makes it defensible to act on a signal that is not perfect.

What this is not

It has never seen a real transaction — every session is generated, because no public dataset of AI-agent purchases exists yet. Nothing here executes a payment: remediation decides, it does not capture. There is no mandate store, no auth, no multi-tenancy. It is a validated architecture with one real failure mode found and closed, not production payments infrastructure.
